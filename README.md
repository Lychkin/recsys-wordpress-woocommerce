# Рекомендательная система для e-commerce на WordPress и WooCommerce

## Описание проекта

Этот проект реализует **персонализированную рекомендательную систему** для интернет-магазина мебели на платформе **WordPress + WooCommerce**.

Система использует:

- историю покупок,
- просмотры товаров,
- добавления в корзину,
- данные товаров

для обучения **модели гибридной фильтрации**, которая рекомендует пользователям релевантные товары и похожие позиции.

Модель написана на **Python** и может интегрироваться в WordPress через **FastAPI**.

## Идея рекомендательной системы

Рекомендательная система построена по гибридному принципу и объединяет:

1. Коллаборативную фильтрацию (Implicit ALS https://github.com/benfred/implicit).
2. Контентную фильтрацию (TF-IDF).
3. Модуль популярных товаров (Popularity-Based Recommendation).

Каждый из методов решает разные задачи:

| Метод      | Решаемая задача                                                                  |
| ---------- | -------------------------------------------------------------------------------- |
| ALS        | поиск товаров, интересных пользователю на основе поведения похожих пользователей |
| TF-IDF     | поиск товаров, похожих на ранее интересовавшие пользователя                      |
| Popularity | рекомендации при отсутствии информации о пользователе                            |

```
    WordPress + WooCommerce
      │               │
      │          JS + WP Hooks
      │               │
WooCommerce API  FastAPI (/event)
      │               │
      ├────────────────
      ▼
      │
fetch_products.py + fetch_events.py → products.parquet + raw_events.parquet
      │
      ▼
prepare_data.py → events.parquet
      │
      ▼
train_hybrid.py → hybrid_model.pkl
      │
      ▼
FastAPI (/recommend?user_id={user_id}&k={recommendations_number} )
      │
      ▼
WordPress recommendations
```

## Авторизация

Для взаимодействия с **внешним API** рекомендательной подсистемы REST-запросы отправляются из **серверной части веб-приложения** (server-side API integration). При таком подходе:

1. Нет проблем с CORS
2. Юзер не увидит адрес API сервиса
3. Юзер не увидит токены доступа или API-ключи
4. Пользователи изолированы от внутренней архитектуры, они не знают как и откуда получены рекомендации, какой сервис их сгенерировал

При этом, реализована проверка подлинности запроса с помощью **секретного ключа**, известного только на WordPress backend и FastAPI. Каждый запрос на любой из доступных эндпоинтов FastAPI, будет проверяться на его наличие.

Когда пользователь делает открывают страницы WordPress с _рекомендациями_:

- браузер делает HTTP запрос к WordPress
- WordPress обрабатывает пользовательский запрос и добавляет **секретным авторизационный ключ** в **специальный заголовок** (по умолчанию _"X-Recommender-API-Key"_)
- WordPress отправляет этот запрос к FastAPI-сервису рекомендаций, уже подписанный секретным ключем
- FastAPI проверяет ключ, ведь он знает его
- FastAPI возвращает список рекомендаций в виде JSON
- WordPress генерирует HTML с учётом списка рекомендуемых товаров
- Готовая HTML-страница уходит пользователю

**Секретный ключ** в такой архитектуре — это просто длинная и криптографически случайная строка, которая используется для server-to-server авторизации.

## API

| Endpoint                    | Назначение                |
| --------------------------- | ------------------------- |
| `/recommend/user/{user_id}` | персональные рекомендации |
| `/recommend/item/{item_id}` | похожие товары            |

Пример ответа:

```json
[
  { "item_id": "55", "score": 2.91 },
  { "item_id": "14", "score": 2.12 }
]
```

## Как запустить

1. Установить зависимости:

```bash
pip install -r requirements.txt
```

2. Собрать данные:

```bash
python3 -m app.etl.fetch_events
```

3. Подготовить датасет:

```bash
python3 -m app.etl.prepare_data
```

4. Обучить модель:

```bash
python3 -m app.ml.train_als
```

5. Запустить API:

```bash
python3 -m app.main
```
